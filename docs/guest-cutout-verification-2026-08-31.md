# 하객 공용 컷아웃 리그 전환 검증 기록

상태: 로컬 구현 및 검증 완료, 전체 시각 승인 대기  
배포 상태: 커밋·푸시·PR·main 병합·Pages 배포 미실행

## 결과 요약

- 12명 모두 편집 가능한 공용 3등신 골격, 방향별 벡터 파츠, 의상 유형별 키프레임을 사용한다.
- 총 192개 고해상도 프레임은 192×288이며 12개의 768×1152 보행 시트로 자동 출력된다.
- 2·4번 프레임은 동일한 중립 포즈이고, 1·3번은 서로 다른 발이 전진한다.
- 실제 48×72 표시 환산 최대 중심 이동은 0.206px다.
- 투명 픽셀 RGB 오염과 캔버스 외곽 불투명 픽셀은 모두 0이다.
- 방향별 실제 파츠와 반전본의 최소 차이는 1.342%로, 오른쪽 방향을 단순 반전하지 않는다.
- 흰색·크림색을 포함한 캐릭터별 선언 의상색 보존 검사가 모두 통과했다.
- 일반 빌드 전후 12명 편집 원본 36개 파일의 SHA-256 목록이 동일해 원본을 덮어쓰지 않는다.

자동 감사 원문은 `character-assets/generated/cutout-v1/audit.json`에 생성된다. 이 파일과 최종
PNG는 `pnpm characters:build-cutouts && pnpm characters:audit-cutouts`로 다시 만들며 Git에는
원본 리그와 생성 코드만 기록한다. 공용 제작 레시피에서 원본을 다시 만드는 작업은
`pnpm characters:sync-cutout-sources`를 명시적으로 실행할 때만 일어난다.

## 실제 UI 검증

390×844, DPR 2의 로컬 프로덕션 빌드에서 다음을 확인했다.

- 선택 화면의 12명 전환: 모두 새 리비전 URL, 로드 완료, 고해상도 시트 폭 768px
- 정면·오른쪽·뒷면·왼쪽 방향 전환: 표시 방향과 실제 시트 행 일치
- 보행 재생·정지: 0·1·2·3 프레임 순환 후 정지 시 중립 프레임 유지
- 선택 화면: 96×144, 게임 맵: 48×72
- 게임 이동: 실제 조이스틱 입력에서 네 보행 프레임과 오른쪽 이동 방향 확인
- 12명 선택·게임용 24개 보행 URL: 모두 HTTP 200
- 캐릭터 리소스 로드 오류: 없음
- 서비스 워커: 새 worker가 페이지를 제어하며 새 리비전만 캐시, 이전 하객 리비전 0개

기본 캐릭터의 서비스 워커 캐시·프로덕션 빌드·로컬 생성물 SHA-256은 다음처럼 일치했다.

| 자산 | SHA-256 |
| --- | --- |
| 게임 idle | `59bf6c52af47a752169004004d8a8fb79019f05e078f4c7ccaaf0d0b9fbd8575` |
| 게임 walk | `3a672ede5fee41e4f2205b0f6fbea7a44bbd62f8e2f51f98b20b6a8b8210301c` |
| 선택 idle | `c1923e55db72268e72bb5c9071ad396875a10d9ab5460ed667685861016c0973` |

서비스 워커 제어 상태에서 오류 로그를 비운 뒤 다시 로드했을 때 페이지 오류는 0건이었다.
하객 자산 URL은 모두 200이었고 서비스 워커 캐시 응답 해시는 위와 같이 일치했다.

마지막 시각 회귀 한 건은 12명 하객 영역이 기존 PNG에서 새 컷아웃 리그로 바뀐 의도된
차이를 감지한 것이다. 기존 허용치 0.500%는 변경하지 않았고 베이스라인도 자동 승인하지
않았다. 전체 검수표와 실제 UI 캡처를 사람이 승인한 뒤에만 새 베이스라인을 명시적으로
승격하고 전체 테스트를 다시 수행한다.

## 제거한 임시 보정

- 머리·어깨 밴드 복사
- 프레임별 몸통·얼굴 크기 변형
- 발 영역 픽셀 교체
- 중립·보행 프레임의 부분 이미지 합성
- CSS 가상 요소의 머리·의상 클립 복사와 프레임별 위치 보정
- 비대칭 요소를 포함한 좌우 방향의 무조건 반전
- 생성 단계의 최종 PNG 헤어 가장자리 픽셀 제거

기존 `character-assets/source/guests*`는 삭제하지 않고 참고용 보관본으로 유지하되, 기본
런타임 생성 경로에서는 읽지 않는다.

## 승인 게이트

현재 결과는 로컬 프로덕션 빌드까지 검증됐으나 운영 배포 결과가 아니다. 전체 시각 승인 후
새 베이스라인 승격, 전체 테스트 재실행, 관련 파일만 커밋, 푸시, PR, main 병합, GitHub Pages
배포 및 운영 URL·서비스 워커·운영 자산 해시 검증을 진행한다. Worker 코드는 변경하지 않았으므로
Worker는 재배포하지 않는다.
