# 3번 접지·캐시 정밀 검수 — 2026-09-08

## 결론

이동 시각 품질은 통과 처리하지 않는다. 실제 게임의 월드 위치가 30px씩 불연속적으로 바뀌고 보행 프레임도 같은 순간에 넘어간다. 원본 리그의 보폭만 늘여 해결할 문제가 아니다. 그림·키프레임 및 게임 동작은 이번 측정에서 변경하지 않았다.

## 실제 게임 측정

agent-browser, 390×844, 로컬 파일럿 5193, 우리 집 맵에서 가상 조이스틱에 상하좌우 키 입력을 전달했다. `scripts/guest03-contact-probe.js`가 requestAnimationFrame마다 월드 좌표와 화면 좌표, 방향, 프레임을 기록한다. 카메라 이동을 발 이동으로 오인하지 않도록 판정은 월드 좌표로 한다. 플레이어 좌표나 React 상태를 직접 조작하지 않았다.

- 위 133개, 아래 136개, 왼쪽 117개, 오른쪽 124개 샘플.
- 네 방향 모두 샘플 사이 최대 위치 변화 30px. 이동 이벤트 사이는 대부분 같은 위치를 유지한다.
- 코드의 기본 이동 간격 240ms와 최초 지연 300ms, 타일 크기 30px가 이 동작을 설명한다. 정상 반복 구간 이론 속도는 125px/s, 네 포즈 한 주기는 960ms/120px다.
- 독립 신발 렌더링의 밑창 끝 2개 불투명 행에서 기준점을 측정하고 48×72 크기로 환산했다. 실제 좌표 변화와 합산한 동일 발의 포즈 간 이동은 측면 약 26.34~33.66px였다.

이 수치는 **동일 발 기준점의 포즈 간 월드 이동**이지 접지 슬립 26~34px라는 뜻은 아니다. 현재 원본에 지면 접촉 시작/종료 정보가 없고, 공중 발도 이동한다. 발목 자체가 꺾이는 문제와도 구분한다. 정확한 접지 판정에는 stance/contact 구간과 시간 연속적인 움직임이 필요하다.

원본 샘플 및 분석은 `animation/integrated-v2/contact-samples.json`, `contact-audit.json`에 보존했다. 분석 재현: `node scripts/audit-guest03-contact.mjs`.

## 권장 다음 구현 범위

원화와 16프레임은 그대로 잠그고, 3번 로컬 시범에서만 **논리 타일 이동과 화면 표시 위치를 분리하는 보간**을 검토한다. 충돌·포털·서버 좌표는 건드리지 않는 범위를 먼저 설계한다. 그 다음 보행 위상을 시간/실제 표시 이동 거리 및 원본 리그의 접지 구간과 맞춘다. 단순히 CSS transition만 넣거나 전역 이동 속도를 낮추는 것을 해결로 간주하지 않는다. 이동 거리와 작은 4포즈 보폭의 불일치는 보간만으로 사라지지 않는다.

이 변경은 기존의 원화/키프레임 수정과 다른 게임 이동 표현 작업이므로 이번 감사에서 전역 이동 로직을 변경하지 않았다. 운영 배포하지 않는다.

## 서비스 워커 캐시 — 별도 로컬 실험

`node scripts/serve-guest03-cache-canary.mjs`로 5194의 격리된 localhost origin을 사용했다. 기존 `client/dist/service-worker.js`를 그대로 등록하고 일반 이미지 요청으로 같은 캐릭터 경로의 `?v=before`와 `?v=after`를 순서대로 로드했다. 실제 Cache Storage에서 응답을 읽어 SHA-256을 계산했다.

- before / integrated-v1: `464a889d611c4ab31551c3c1747efbb595ae835c11ff47273d54309cb01c5bf1`
- after / integrated-v2: `84827750596d0a1b6e32db739f3e29927911164b6d2c61e13c8fb834ad22fabe`

두 캐시 응답은 서로 다르고 각각 로컬 생성물과 일치했다. 증거: `animation/integrated-v2/cache-canary.json`. 테스트 전용 워커 등록과 캐시는 해당 origin에서 제거했다. 이는 **버전이 다른 이미지 URL의 캐시 구분 검증**이며 실제 운영 URL 배포, 새 워커 설치/활성화 업그레이드, 같은 URL 덮어쓰기 갱신 검증이 아니다. 운영에서는 자산 revision을 새로 부여해야 한다.
